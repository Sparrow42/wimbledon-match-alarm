# wimbledon-match-alarm

指定した試合（選手同士の組み合わせ）がESPNの公開スコアボードで状態変化した瞬間に、Windows PC上で音とポップアップを鳴らして知らせるアラームです。深夜に行われる試合を見逃さないために作りました。ATP・WTAのデータを使うため、四大大会（ウィンブルドン・全米オープン等）を含む主要なプロテニス大会で使えます。

## できること

- 60秒間隔（変更可）でESPNの公開API（`site.api.espn.com`）をポーリングし、監視対象の試合ステータスをチェック
- 試合が始まった瞬間（`Scheduled` → `In Progress`）に、Windows標準のアラーム音をループ再生 + 画面最前面にポップアップ表示
- 「前の試合」を設定しておくと、対象の試合自体が始まるのを待たず、前の試合が終了した時点（＝ウォームアップ・招集が始まるタイミング）でアラームを鳴らせる。試合開始ちょうどではなく、数分前に起きたい場合に使う
- 試合の「終了」を検知して知らせることもできる（`trigger: "end"`）。結果が気になる試合が終わったタイミングで気付きたい場合に使う
- ポップアップの「停止」ボタンを押すまで音・表示が続く
- 監視対象は `config.json` を編集するだけで追加・変更できる（コード変更不要）
- 一度アラームを鳴らした試合は `state.json` に記録され、スクリプトを再起動しても二重に鳴らない

## 必要なもの

- Windows 10/11 PC（標準搭載の `curl.exe` を使ってAPI通信するため。Windows 10 1803以降・Windows 11なら標準で入っています）
- Python 3.x（標準ライブラリのみ使用。追加のpipインストール不要）

## セットアップ

1. このリポジトリをダウンロード（`git clone` または ZIP展開）
2. Pythonがインストールされていることを確認
   ```
   python --version
   ```
3. `config.json` を開き、監視したい試合を設定する（下記「設定方法」参照）

## 使い方

### 起動

フォルダ内の `start_watch.bat` をダブルクリックするだけ。コンソール画面が開いたまま、監視状況（各試合の現在ステータス）がログ表示され続けます。

コマンドラインから直接起動する場合:
```
python watch_and_alarm.py
```

止めるときはコンソールで `Ctrl+C`。

### 音・ポップアップだけを今すぐテストしたいとき

```
python watch_and_alarm.py --test-alarm
```
API通信をせず、その場でアラーム（音+ポップアップ）を鳴らします。動作確認用です。

## 設定方法（`config.json`）

```json
{
  "poll_interval_sec": 60,
  "watches": [
    {
      "label": "望月慎太郎 vs シナー（4回戦・センターコート第3試合）",
      "league": "atp",
      "players": ["Mochizuki", "Sinner"],
      "previous_match": {
        "players": ["Sabalenka", "Osaka"]
      },
      "enabled": true
    },
    {
      "label": "鄭欽文 vs プリダンキナ（全米オープン）",
      "league": "wta",
      "players": ["Zheng", "Pridankina"],
      "trigger": "end",
      "enabled": true
    }
  ]
}
```

| 項目 | 説明 |
|---|---|
| `poll_interval_sec` | ポーリング間隔（秒）。デフォルト60秒 |
| `label` | ポップアップやログに表示する試合名（自由記述） |
| `league` | `atp`（男子シングルス）または `wta`（女子シングルス） |
| `players` | 選手の姓（の一部）を2つ配列で指定。両方が試合の対戦カードに含まれるものを検索します（大文字小文字は区別しません） |
| `trigger`（省略可） | `"start"`（デフォルト）は試合開始を検知。`"end"`にすると、代わりに試合終了を検知してアラームを鳴らす |
| `previous_match`（省略可、`trigger: "start"`のときのみ有効） | 同じコートの直前の試合を指定すると、対象の試合が始まるのを待たず、直前の試合が終了した時点でアラームを鳴らす。`players`（必須、書式は上と同じ）と、リーグが違う場合のみ`league`を指定できる |
| `enabled` | `false` にするとその試合の監視を一時的に無効化 |

新しい試合を追加したいときは、`watches` 配列に同じ形式のオブジェクトを追記するだけです。大会名を指定する項目はありません。ESPNの公開APIが現在開催中の大会を自動的に返すため、`league`（atp/wta）と選手名だけで、どの大会の試合でも見つかります。

### `previous_match` の挙動について

- `previous_match` を設定すると、対象の試合が `Scheduled` の間は直前の試合のステータスを見に行き、それが `Final`（終了）になった瞬間にアラームを鳴らします。試合そのものが `In Progress` になるのを待たないため、ウォームアップ・招集が始まる数分前に気付けます。
- 対象の試合自体が先に `In Progress` になっていた場合（`previous_match` の情報が取得できない場合のフォールバックとして）は、その時点でアラームを鳴らします。
- `previous_match` を省略した場合は、これまで通り対象の試合が `In Progress` になった瞬間にアラームを鳴らします。
- 同じ2選手が大会中に複数回対戦する場合（別ラウンドなど）は、現在時刻に最も近い試合を自動的に選びます。
- 前の試合が「終了」と判定されるのは2回連続でポーリングして確認できた場合のみです（1回だけだと、試合途中でデータが一時的に乱れて誤って鳴ってしまうことがあるため）。

## 注意事項

- 試合開始の検知は「ESPNのスコアボードにその試合が `In Progress` として反映されたタイミング」に依存します。反映まで数十秒〜数分のラグが出ることがあります。
- 大会期間中（予選〜決勝）の全試合データがAPIレスポンスに含まれるため、初戦から順に該当の対戦カードを検索しています。トーナメント表がまだ確定していない段階（対戦相手未定など）では試合が見つからない旨がログに表示されます。
- ESPNへのAPI通信はWindows標準搭載の`curl.exe`経由で行っています。PythonのHTTPライブラリ（urllib等）で直接リクエストすると、ブラウザを装ったUser-Agentがかえって不審に扱われ、ESPN側のBot対策(Akamai)に403で弾かれることを確認したため、curlのデフォルトUser-Agentのままリクエストしています。まれに一時的に403が返ることがありますが、その場合は数秒空けて自動的にリトライします。
- 監視は同じPC・同じネットワークで実行し続ける必要があります（スリープ状態だとポーリングが止まります。電源設定でスリープを無効にするか、就寝前にPCを起こしたままにしておいてください）。詳しい設定方法は下記「PCがスリープしないようにする」を参照。

## PCがスリープしないようにする

監視スクリプトを深夜まで動かし続けるには、PCがスリープしない設定にしておく必要があります。

### 方法1: 設定アプリから

1. `Win + I` で設定を開く
2. 「システム」→「電源とバッテリー」（ノートPCの場合は「電源とスリープ」）
3. 「画面とスリープ」の「スリープ状態」を、電源接続時・バッテリー駆動時ともに「なし」に変更

### 方法2: コマンドで一括変更（`powercfg`）

管理者権限のPowerShellまたはコマンドプロンプトで:

```
powercfg /change standby-timeout-ac 0
powercfg /change standby-timeout-dc 0
```

- `-ac` は電源接続時、`-dc` はバッテリー駆動時の設定（デスクトップPCでは`-dc`は無視されます）
- `0` は「スリープしない」という意味

元の設定に戻したいときは、`0`の代わりに元々設定されていた分数（例: `30`）を指定して同じコマンドを実行してください。
